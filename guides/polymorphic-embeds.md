# Polymorphic Embeds

Use `polymorphic_embeds_one/2` when a field can contain one of several schema types, and
`polymorphic_embeds_many/2` when a list can contain a mixture of those types. Strukt integrates
`PolymorphicEmbed` into its schema DSL, generated types, casting, validation, and JSON support.
The dependency is included with Strukt; no additional import or manual call to
`PolymorphicEmbed.cast_polymorphic_embed/3` is needed inside a Strukt schema.

## Define the Types

This example models a reminder delivered by email or SMS. Define each variant as a separate
Strukt module, then list the allowed modules in the parent's `types:` option.

```elixir
defmodule EmailChannel do
  use Strukt

  @primary_key false
  defstruct do
    field :address, :string, source: :emailAddress, required: true
    field :label, :string, default: "personal"
  end
end

defmodule SMSChannel do
  use Strukt

  @primary_key false
  defstruct do
    field :number, :string, required: true
  end
end

defmodule Reminder do
  use Strukt

  @derives [Jason.Encoder]
  defstruct do
    field :title, :string

    polymorphic_embeds_one :channel,
      types: [email: EmailChannel, sms: SMSChannel],
      on_replace: :update,
      on_type_not_found: :changeset_error,
      required: [message: "choose a channel"]

    polymorphic_embeds_many :fallback_channels,
      types: [email: EmailChannel, sms: SMSChannel],
      on_replace: :delete,
      on_type_not_found: :changeset_error
  end
end
```

The keys `:email` and `:sms` are the external type tags, not field names or module names.
The default discriminator key is `__type__`. It belongs to the input and serialized data;
there is no need to declare it as a field in the child schemas.

The children use `@primary_key false` because these small value objects do not need IDs.
Omit that attribute to retain Strukt's usual autogenerated `uuid`. When constructing variants
with IDs, prefer their `new/1` functions to raw struct literals so autogenerated values are set.

| Option | Single embed | List of embeds |
| --- | --- | --- |
| `types:` | Allowed tag/module pairs | Allowed tag/module pairs |
| `on_replace:` | Must be `:update` | Must be `:delete` |
| Default value | `nil` | `[]` |
| `required:` | Rejects an absent or cleared value | Rejects an empty list |
| `type_field_name:` | Defaults to `:__type__` | Defaults to `:__type__` |
| `on_type_not_found:` | `:changeset_error` by default; also `:raise` or `:nilify` | `:changeset_error` by default; also `:raise` or `:ignore` |

`:nilify` clears an unresolvable single embed; `:ignore` drops unresolvable list entries.
These policies also apply to malformed type tags and explicit unknown tags when a single
embed already has a value. Only an omitted tag can fall back to the current single variant.
Unknown parent discriminator values use the same configured policy.
These options apply when casting cannot determine a type, not to arbitrary invalid input shapes
or JSON loading. Parent required validation still applies. Keep `:changeset_error` when invalid
input should be reported to the caller.

## Create from Parameters

Map parameters select a variant with the discriminator. Atom or string tags are accepted,
as are atom or string parameter keys. Nested `source:` mapping works through `new/1` and
`change/2`, just as it does for ordinary embeds.

```elixir
{:ok, reminder} =
  Reminder.new(%{
    "title" => "Appointment",
    "channel" => %{
      "__type__" => "email",
      "emailAddress" => "person@example.com",
      "label" => "work"
    },
    "fallback_channels" => [
      %{"__type__" => "sms", "number" => "+15555550100"},
      %{"__type__" => "email", "emailAddress" => "backup@example.com"}
    ]
  })

%EmailChannel{address: "person@example.com", label: "work"} = reminder.channel
[%SMSChannel{}, %EmailChannel{}] = reminder.fallback_channels
```

Each list element selects its own type. Maps are cast and validated using the selected
module's `changeset/2`, including that module's inline and custom validations.

## Update or Switch Types

Include the discriminator in partial map updates, especially when using source names: Strukt
needs to identify the child module before normalizing those names. With the same type,
omitted child fields retain their values. Switching to a different declared type starts with
the new schema's defaults rather than carrying over the previous variant's fields.

```elixir
{:ok, updated} =
  reminder
  |> Reminder.change(channel: %{__type__: :email, emailAddress: "new@example.com"})
  |> Reminder.from_changeset()

%EmailChannel{address: "new@example.com", label: "work"} = updated.channel

{:ok, sms_reminder} =
  updated
  |> Reminder.change(channel: %{__type__: :sms, number: "+15555550101"})
  |> Reminder.from_changeset()

%SMSChannel{number: "+15555550101"} = sms_reminder.channel
```

A supplied list defines the resulting list membership and order; it does not append entries.
For partial map updates, Strukt first matches supplied primary keys against current entries
of the same module, including pending changes. This supports `id`, `uuid`, and composite keys;
keys are cast to their declared types before comparison. Include the primary keys when
reordering or removing entries so retained items keep their own data.

If no primary key is supplied, Strukt uses the entry at the same position when its module
matches. An explicit nil, invalid, incomplete, or unmatched key never borrows data from that
position. For schemas without primary keys, supply complete values when reordering entries.
Omitting the entire field keeps the existing list.

### Select a Single Embed's Type from Its Parent

Set `use_parent_field_for_type:` to select a single embed's variant from another field
on the parent. The parent field's cast value is used, including an `Ecto.Enum` value and
pending changes. `new/1` and `change/2` normalize source aliases using that selected variant.

```elixir
defmodule ParentSelectedReminder do
  use Strukt

  defstruct do
    field :kind, Ecto.Enum, values: [:email, :sms]
    polymorphic_embeds_one :channel,
      types: [email: EmailChannel, sms: SMSChannel],
      use_parent_field_for_type: :kind,
      on_replace: :update
  end
end

{:ok, selected} =
  ParentSelectedReminder.new(kind: "email", channel: %{emailAddress: "person@example.com"})

{:ok, switched} =
  selected
  |> ParentSelectedReminder.change(kind: "sms", channel: %{number: "+15555550103"})
  |> ParentSelectedReminder.from_changeset()

%SMSChannel{number: "+15555550103"} = switched.channel
```

When changing the parent discriminator, supply the embed parameters too: omitting the embed
preserves its current value. A child type tag is optional with this configuration; if supplied,
it must agree with the parent discriminator or `polymorphic_embed` raises.

### Already Constructed Structs

Declared variant structs can be passed directly, and lists can mix them with parameter maps.
The order is preserved:

```elixir
{:ok, sms} = SMSChannel.new(number: "+15555550102")

{:ok, mixed} =
  reminder
  |> Reminder.change(
    fallback_channels: [sms, %{__type__: :email, emailAddress: "other@example.com"}]
  )
  |> Reminder.from_changeset()

[^sms, %EmailChannel{address: "other@example.com"}] = mixed.fallback_channels
```

Struct inputs are treated as already cast and validated: their child validation callbacks are
not rerun. Construct them with the variant's `new/1` if validation is needed. Structs from
undeclared modules, scalar values, and `nil` elements inside a list produce field errors.

## Validation and Errors

`required:` on the parent field checks that a channel is present; child rules validate its
contents. Missing required child data is available through the nested changeset. Use
`PolymorphicEmbed.traverse_errors/2` to collect nested polymorphic errors:

```elixir
{:error, invalid} = Reminder.new(channel: %{__type__: :email})

errors = PolymorphicEmbed.traverse_errors(invalid, fn {message, _opts} -> message end)
%{channel: %{address: ["can't be blank"]}} = errors

{:error, unknown} = Reminder.new(channel: %{__type__: :push, token: "abc"})
true = Keyword.has_key?(unknown.errors, :channel)

{:error, missing} = Reminder.new()
{"choose a channel", _opts} = Keyword.fetch!(missing.errors, :channel)
```

For a new embed, a nonempty map whose type cannot be determined produces a field error with
`:changeset_error`. An existing single embed can fall back to its current type when a tag is
missing or unrecognized; this upstream behavior means `on_type_not_found` is not a strict
validator for every supplied tag. Use declared tags, and validate incoming tags separately if
your application requires unknown tags to be rejected on every update.

### Clear an Embed

Omitting a field preserves its current value. To clear it explicitly, pass `nil` for a single
embed or `[]` for a list, subject to required validation.

| Parameter | Result through `new/1`, `change/2`, or `changeset/2` |
| --- | --- |
| Field omitted | Keep current value on update; use default on creation |
| Single embed set to `nil` | Clear it, or fail parent required validation |
| List set to `nil` or `[]` | Set it to `[]`, or fail parent required validation |
| List containing `nil` | Invalid element, not a placeholder |

`Reminder.channel` is required, so clearing it fails. The fallback list is optional:

```elixir
{:error, cannot_clear} =
  reminder |> Reminder.change(channel: nil) |> Reminder.from_changeset()

{"choose a channel", _opts} = Keyword.fetch!(cannot_clear.errors, :channel)

{:ok, no_fallbacks} =
  reminder |> Reminder.change(fallback_channels: []) |> Reminder.from_changeset()

[] = no_fallbacks.fallback_channels
```

For an optional single embed, omit `required:` or use `required: false` to allow clearing.

## Direct Changeset APIs

The generated `changeset/2` and `changeset/3` functions also cast polymorphic fields. They use
schema field names rather than `source:` aliases, including inside child maps:

```elixir
changeset =
  Reminder.changeset(%Reminder{}, %{
    channel: %{__type__: :email, address: "direct@example.com"}
  })

{:ok, %Reminder{channel: %EmailChannel{address: "direct@example.com"}}} =
  Reminder.from_changeset(changeset)
```

For a partial update to an existing single embed, `change/2` also normalizes child `source:`
aliases when the type tag is omitted, using the current variant, including pending changes.

`change/2` also accepts an existing changeset. Calling `validate/1` alone runs validation rules
on the changeset; it does not cast raw polymorphic parameters or validate every already-stored
child struct again.

## JSON Round-Trips

With `@derives [Jason.Encoder]` on the parent, serialization includes the type tag and each
variant's source names. Child modules do not need their own derived encoder for this nested
serialization path.

```elixir
json = Jason.encode!(reminder)

%{"channel" => %{"__type__" => "email", "emailAddress" => "person@example.com"}} =
  Jason.decode!(json)

{:ok, ^reminder} = Reminder.from_json(json)
```

`from_json/1` uses Ecto loading, not changeset validation. It can load nil into required fields,
and an unknown JSON type raises by default even when casting uses `on_type_not_found:
:changeset_error`. A JSON `null` polymorphic list loads as `nil`; use `[]` to represent an empty
list. See [JSON Support](json.md) for the loading contract and error behavior.

## Customize the Discriminator

Set `type_field_name:` on the parent field to use a different key. The same key is then used
for map casting and JSON serialization/loading. The older `type_field:` spelling is deprecated.

```elixir
defmodule TaggedReminder do
  use Strukt

  defstruct do
    polymorphic_embeds_one :channel,
      types: [email: EmailChannel, sms: SMSChannel],
      type_field_name: :kind,
      on_replace: :update
  end
end

{:ok, tagged} = TaggedReminder.new(channel: %{kind: "sms", number: "+15555550103"})
%SMSChannel{number: "+15555550103"} = tagged.channel
```

You can alternatively infer a variant from incoming field names with a type declaration such
as `types: [email: [module: EmailChannel, identify_by_fields: [:emailAddress]]]`. These names
refer to the input keys, before `source:` normalization. Strukt preserves the inferred tag
through normalization, including for lists and custom discriminator keys. Explicit type tags
are preferable when variants share field names.

Strukt also generates a union of the declared variant types for each polymorphic field.
Optional single embeds include `nil`; required single embeds omit it. List fields contain
lists of the variant union. As with other generated types, raw structs and unvalidated JSON
loads are not guaranteed to satisfy the schema's validation constraints.
